# LLM Sycophancy Analysis

Analyze how LLMs agree, challenge, or evade across a structured prompt battery, then score and visualize their stylistic sycophancy profiles.

This repo collects model responses via OpenRouter, scores them with an LLM judge using structured JSON outputs, aggregates Sycophancy Stylometric Signatures (SSS), and builds a similarity network with community structure and bridge highlights.

See detailed methodology and metrics in `docs/methodology.md` and `docs/sycophancy_index_metrics.md`.

## Key Features

- Sycophancy prompt battery with stance, strength, persona, and harmfulness metadata.
- LLM-judge scoring via OpenRouter structured outputs (configurable model and routing).
- Heuristic fallback path available in code, but the default configuration uses LLM judge.
- Aggregated SSS metrics (AOS, CCR, HVS, DAC, AE, FLAT, etc.) + Sycophancy Index (SI).
- Similarity matrix, k-NN graph + Leiden communities, MST backbone, and bridge detection.
- Reusable utilities to combine prior runs and regenerate visuals with an LLM judge pass.

## Quickstart

Prereqs
- Python 3.10+ (3.11 recommended)
- uv (recommended for speed/isolation): https://docs.astral.sh/uv/
- OpenRouter API key in your environment or .env: `OPENROUTER_API_KEY=...`

Setup
- Create venv: `uv venv`
- Install deps: `uv pip install -r requirements.txt`

Run: full pipeline
- macOS/Linux: `uv run python main.py pipeline --api-key $OPENROUTER_API_KEY --save-prefix results/run_001 --interactive`
- Windows (PowerShell): `uv run python main.py pipeline --api-key $Env:OPENROUTER_API_KEY --save-prefix results/run_001 --interactive`

Notes
- `--interactive` opens a quick menu to toggle scoring options and choose the judge model/params.
- The default config enables the LLM judge (`SCORING_CONFIG["USE_LLM_JUDGE"] = True`).
- If you do not provide an API key, stages that call models (`all`, `collect`, `score`) will exit.

## Common Tasks

- Export the prompt battery only:
  - `uv run python main.py export-prompts dataset/prompt_battery.json`

- Run a specific stage (non-interactive examples):
  - Collect: `uv run python main.py pipeline --stage collect --api-key $OPENROUTER_API_KEY --save-prefix results/run_001`
  - Score:   `uv run python main.py pipeline --stage score --api-key $OPENROUTER_API_KEY --save-prefix results/run_001`
  - Viz:     `uv run python main.py pipeline --stage viz --save-prefix results/run_001`

  Tip: The "viz" stage expects artifacts generated by prior steps. Running `--stage all` is the simplest way to ensure everything needed exists.

- Filter models by slug or name (matches `sycophancy_analysis/api/config.py`):
  - `--include_slugs "openai/gpt-4.1,anthropic/claude-3.5-haiku"`
  - `--exclude_slugs "openai/gpt-5-chat"`
  - `--include_names "Gpt 4.1,Gemma 3 12b"`
  - `--exclude_names "Gpt 5"`

- Combine prior runs and rescore with the LLM judge (recommended):
  - `uv run python scripts/combine_runs.py --prefixes results/run_001,results/run_002 --save-prefix results/combined_001_002 --api-key $OPENROUTER_API_KEY`

- evaluating LLM judge models
  - uv run python sycophancy_analysis/evaluate_llm_judges/evaluate_single_model.py \
    --model sonoma-sky-alpha \
    --sample-n 140 \
    --output-dir evaluation_results \
    --verbose

### Combine latest run with an existing combined file

Create a new merged JSON from an existing combined JSON and a latest run, without modifying the originals. The tool deduplicates by `(model, prompt_id)` keeping the newest by `run_id`.

- Windows (PowerShell):

```
uv run python scripts/combine_responses.py `
  "results/combined_run_0c_1_1b/responses_combined.json" `
  "results/run_2b/responses/run_20250912_190809/responses.json" `
  --output "results/combined_run_0c_1_1b_2b/responses_combined.json" `
  --format json `
  --pretty `
  --dedup-strategy latest
```

Notes:
- Omit `--append-to` if you do not want to touch `results/final_responses.json`.
- JSON and JSONL inputs are supported; you can also use the per-run CSV if preferred.
- The output path controls where the new combined file is written.

### Build a text-based model network from RAW responses

This creates a new model-level network using TF‑IDF cosine similarity over the raw response text (independent of SSS). This is different from the stylometric network, which uses SSS vectors.

- Windows (PowerShell):

```
uv run python scripts/build_text_network.py `
  "results/combined_run_0c_1_1b_2b/responses_combined.json" `
  --save_prefix "results/textnet_0c_1_1b_2b" `
  --knn_k 8 `
  --leiden_resolution 1.0 `
  --bridge_threshold 0.5 `
  --stop_words english `
  --min_df 2 `
  --ngram_max 2 `
  --fig_width 20 `
  --fig_height 22
```

What it does:
- Keeps the latest response per `(model, prompt_id)`.
- Concatenates each model’s responses into a single document.
- Computes TF‑IDF features and cosine similarity between models.
- Builds a k‑NN graph (Leiden communities) and MST backbone.

Outputs (under the chosen `--save_prefix`):
- `text_network.png` — network image. Use `--fig_height/--fig_width` to control size.
- `text_heatmap.html` — similarity heatmap (saved if Altair is available).
- `model_response_counts.csv` — per‑model counts of unique prompts extracted.
- Matrices + metadata via `save_matrices()` and `save_metadata()`.

## Outputs

Using `--save_prefix results/run_001` produces:

- Top-level (flat prefix artifacts)
  - `results/run_001_network.png` — Network graph with MST backbone, communities, bridges.
  - `results/run_001_heatmap.html` — Similarity heatmap (Altair; optional if Altair unavailable).
  - `results/run_001_sycophancy_scores.csv` — SI table (ranked) with intermediate SI terms.
  - `results/run_001_network.meta.json` — Sidecar with layout, communities, metrics, and bridge list.

- Under `results/run_001/` (results directory)
  - `responses/run_YYYYMMDD_HHMMSS/responses.(csv|json)` — Collected responses with request metadata.
  - `sss_scores.(csv|json)` — Aggregated SSS per model.
  - `sss_vectors.json` — SSS vectors used to build the similarity matrix.
  - `similarity_matrix.npy` and `distance_matrix.npy`
  - `model_names.json`
  - `scored_rows.csv` — Per-response LLM-judge outputs (including `pred_label`).
  - `metadata.json` — Comprehensive run metadata (models, scoring config, graph metrics, prompts snapshot).

Combine runs (scripts/combine_runs.py) writes combined results under the chosen prefix directory and also saves a `network.png`, `heatmap.html`, and `sycophancy_scores.csv` in that folder.

## Configuration

- File: `sycophancy_analysis/api/config.py`
  - `SCORING_CONFIG` — enables LLM judge by default and configures:
    - `LLM_JUDGE_MODEL` (OpenRouter slug, configurable in `--interactive` mode)
    - `LLM_JUDGE_TEMPERATURE`, `LLM_JUDGE_MAX_TOKENS`
    - Provider routing via `LLM_JUDGE_PROVIDER_PREFS` (defaults to Cerebras; can be adjusted or forced via `LLM_JUDGE_FORCE_PROVIDER` env var)
  - `MODEL_CONFIGS` — default model list (name + slug), auto-enriched with provider/family info.
  - `OUTPUT_FORMAT` — choose `csv` or `json` for certain artifacts.

Environment & Secrets
- `.env` is supported via `python-dotenv`. Required: `OPENROUTER_API_KEY`. No keys are hard-coded.

Reasoning Support
- Reasoning is detected dynamically per model via OpenRouter `/models` capabilities. If a model supports reasoning, the collector sends a small `reasoning.effort` hint; otherwise it uses a standard token budget. If reasoning or structured outputs are rejected by a provider, calls gracefully retry without those features.

## How It Works

1) Build a balanced prompt battery with stance, strength, persona, and harmfulness flags.
2) Collect model responses via OpenRouter (with optional reasoning support and usage metadata capture).
3) Score each response with the LLM judge (structured JSON schema) and aggregate SSS metrics per model.
4) Compute a similarity matrix from SSS vectors; build a k-NN graph; detect communities (Leiden/greedy fallback).
5) Plot the network (MST backbone, edge thickness = similarity, colors = communities, ring = bridges) and emit supporting metrics and artifacts.

For metric definitions, see `docs/sycophancy_index_metrics.md`. For a deeper dive with diagrams, see `docs/methodology.md`.

## Project Structure

- `main.py` — CLI for the end-to-end pipeline (stages: `all`, `collect`, `score`, `viz`).
- `sycophancy_analysis/`

- `dataset/` — prompt battery and example inputs (`--export_prompts` can populate).
- `results/` — generated artifacts (responses, CSV, vectors, matrices, metadata, plots).
- `docs/`, `notebooks/` — reference and exploration.

## Tips & Troubleshooting

- Altair may be unavailable in some environments; the pipeline logs and skips saving the heatmap if so.
- If `--stage viz` fails on missing inputs, run `--stage all` or make sure SSS and similarity artifacts exist for the same `--save_prefix`.
- Network layout uses UMAP when installed; otherwise it falls back to a spring layout.
- Large model lists can be slow and incur costs; use `--include_*` or `--exclude_*` flags to narrow the set.
